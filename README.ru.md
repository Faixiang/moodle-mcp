# Moodle-Mcp
### Moodle, которым ИИ-агенты действительно могут пользоваться

Задания, дедлайны и файлы курсов читаются напрямую из Moodle Web Service API. Без браузера, без скраперов, без кликов по страницам.

## Зачем это нужно 🎯

Moodle обеспечивает учебные платформы вузов по всему миру, но универсального MCP-сервера для него не было. Сбор данных безголовым браузером медленный, хрупкий и часто упирается в WAF, хотя у Moodle давно есть стабильный и документированный REST API.

Этот проект — недостающий слой: **один Python-файл без зависимостей, шесть инструментов только для чтения**, работает с любым Moodle 3.x/4.x с включёнными Web Services.

```text
Без pip install. Без node. Без браузера. Просто python server.py.
```

## Возможности ✨

### Получение данных
- **Дедлайны в читаемом виде** — задания делятся на «скоро срок», «просрочено» и «без спешки», остаток дней уже посчитан
- **Недельная сводка** — новое + ближайшие сроки + просрочки одним запросом, сразу в готовом виде
- **Файлы курса** — структура разделов и список файлов с прямыми ссылками и датой изменения; только метаданные, без скачивания
- **Встроенная диагностика** — `moodle_site_info` сообщает версию сайта, учётную запись и список функций, реально доступных токену

### Реализация
- **Ноль зависимостей** — только стандартная библиотека Python (`urllib`, `json`, `ssl`)
- **Один файл** — скопируйте `server.py` куда угодно; ни структуры пакета, ни шага сборки
- **stdio JSON-RPC 2.0** — прямое подключение к Claude Desktop, Cursor, Marvis и любому MCP-совместимому клиенту
- **Дружелюбен к WAF** — запросы сериализованы с интервалом 150 мс, потому что настойчивость к Moodle даёт только `502`
- **Только чтение по замыслу** — кода для сдачи, записи на курс, редактирования или удаления не существует

## Инструменты 🧰

| Инструмент | Назначение | Параметры |
|---|---|---|
| `moodle_site_info` | Проверяет токен и возвращает название сайта, версию Moodle, текущего пользователя и доступные функции (диагностика). | — |
| `moodle_list_courses` | Перечисляет все курсы с ID, кратким и полным названием. | — |
| `moodle_recent_updates` | Новое и изменённое за последние N дней (задания, файлы, объявления), от новых к старым. | `days` (по умолчанию 7), `course_ids` |
| `moodle_pending_assignments` | Не сданные задания с разбивкой **скоро срок** / **просрочено** / **без спешки**, с дедлайном и остатком дней. | `ahead_days` (по умолчанию 14), `course_ids` |
| `moodle_course_files` | Структура разделов и файлы одного курса с прямыми ссылками и датой изменения. **Только метаданные, файлы не скачиваются.** | `course_id` |
| `moodle_weekly_digest` | Всё сразу: новое + ближайшие сроки + просрочки + статистика. Рекомендуемая точка входа. | `days` (по умолчанию 7), `ahead_days` (по умолчанию 14) |

## Быстрый старт 🚀

### ① Получить токен

Moodle требует персональный ключ доступа. Выберите вариант под свой сайт:

**A. Веб-интерфейс (рекомендуется, работает и для SSO)**

1. Войдите в свой Moodle
2. Фото профиля → *Настройки* → *Аккаунт* → *Безопасность* → *Управление ключами доступа*
3. Нажмите «Создать», имя `moodle-mcp`, служба *Moodle mobile web service*
4. Скопируйте созданный ключ

**B. Скрипт через мобильную службу (только если на сайте остался локальный пароль)**

```bash
python get_token.py
```

Скрипт получает токен через `/login/token.php` и службу `moodle_mobile_app`, затем сразу проверяет его. Пароль не отображается и не пишется в логи. Для аккаунтов только с SSO вернётся `invalidlogin` — используйте вариант A.

**C. Переменные окружения**

```bash
MOODLE_URL=https://moodle.your-school.edu
MOODLE_TOKEN=your_token_here
```

### ② Настроить

Создайте `config.json` рядом с `server.py` (можно скопировать `config.example.json`):

```json
{
  "url": "https://moodle.your-school.edu",
  "token": "your_token_here"
}
```

Переменные окружения важнее файла.

### ③ Зарегистрировать сервер

Claude Desktop / Cursor (`mcp.json`):

```json
{
  "mcpServers": {
    "moodle": {
      "command": "python",
      "args": ["/absolute/path/to/moodle-mcp/server.py"]
    }
  }
}
```

В `args` укажите абсолютный путь к `server.py`. Если установлено несколько версий Python, направьте `command` на полный путь интерпретатора.

### ④ Проверить

Вызовите из клиента `moodle_site_info`. При верной настройке вернутся название сайта, версия Moodle и данные пользователя. При ошибке смотрите раздел «Частые вопросы».

## Справочник настроек ⚙️

| Ключ | Тип | Обязателен | Описание |
|---|---|---|---|
| `url` / `MOODLE_URL` | строка | Да | Корневой URL сайта без пути в конце |
| `token` / `MOODLE_TOKEN` | строка | Да | Персональный токен из «Управления ключами доступа» |
| `config.json` | файл | Нет | Читается из каталога `server.py` |

Приоритет: переменные окружения → `config.json` → ошибка.

## Примеры использования 💬

> «Что у меня ещё не сдано на этой неделе?»

Агент вызывает `moodle_weekly_digest` и возвращает готовую к чтению сводку:

```text
## Срок в ближайшие 7 дней, не сдано
| CIS225 Data Structures | A10021 Crosswords  | 2026-10-29 23:59 | 3 дня |
| CIS225 Data Structures | A10022 Cow Jogging | 2026-10-29 23:59 | 3 дня |

## Просрочено
| CIS225 Data Structures | A10009 Dancing | 2026-10-11 23:59 | просрочка 15 дней |

## Статистика
Сдано/оценено: 51 ｜ Не сдано всего: 25 (скоро 4, просрочено 14, прочее 7)
```

Другие полезные формулировки:

| Вы говорите | Вызывается инструмент |
|---|---|
| «Что нового в CIS225 на этой неделе?» | `moodle_recent_updates` |
| «Покажи файлы GER405, не скачивай» | `moodle_course_files` |
| «В каких курсах нет просрочек?» | `moodle_pending_assignments` |
| «Мой токен ещё действует?» | `moodle_site_info` |

## Частые вопросы 🤔

<details>
<summary><b>get_token.py возвращает <code>invalidlogin</code></b></summary>

Аккаунт работает только через SSO/OIDC, и `/login/token.php` нечего проверять локальным паролем. Используйте вариант A и создайте токен в «Управлении ключами доступа».
</details>

<details>
<summary><b>Вызов возвращает <code>502</code> или соединение сбрасывается</b></summary>

Это ограничение частоты на WAF сайта. Сервер уже сериализует запросы с интервалом 150 мс; если проблема остаётся, подождите несколько минут и не вызывайте несколько инструментов параллельно.
</details>

<details>
<summary><b>Инструмент возвращает пустой список</b></summary>

Проверьте три вещи: включены Web Services и REST, у аккаунта есть `webservice/rest:use`, фильтр `course_ids` задан верно. Сначала запустите `moodle_site_info`: если список функций очень короткий, администратор открыл только мобильный набор.
</details>

<details>
<summary><b>Не видны дедлайны Turnitin или тестов</b></summary>

Так и должно быть. `turnitintooltwo` и `quiz` — независимые модули без семантики `mod_assign`, этот сервер их не читает. Проверяйте в веб-интерфейсе.
</details>

<details>
<summary><b>У задания дедлайн показан как «not set»</b></summary>

Преподаватель не задал дедлайн для этого задания, считать нечего. Задание всё равно остаётся в списке, чтобы не потерялось.
</details>

<details>
<summary><b>В терминале Windows ломается кириллица</b></summary>

Вывод в UTF-8. В старых консолях выполните `chcp 65001` или используйте Windows Terminal.
</details>

## Безопасность 🔒

- Токен — это **учётные данные**. Храните его только в `config.json` или переменных окружения, не коммитьте в репозиторий; `.gitignore` уже исключает `config.json` и `get_token.log`.
- `get_token.py` не записывает содержимое пароля, только длину, и читает его через `getpass`.
- Все инструменты только читают: даже при утечке токена через этот сервер нельзя ничего изменить или удалить. При утечке отзовите ключ в «Управлении ключами доступа».
- Не публикуйте дампы трафика: `wstoken` передаётся в теле запроса.
