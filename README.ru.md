# moodle-mcp

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português](README.pt-BR.md) · **Русский**

Сервер MCP (Model Context Protocol), который превращает **Web Service API Moodle** в инструменты, напрямую вызываемые ИИ-агентом. Без браузера, без скраперов, без кликов по страницам.

Moodle обслуживает учебные платформы бесчисленных вузов по всему миру, но универсального MCP-сервера для него не существовало. Этот проект закрывает пробел: один файл, никаких зависимостей, шесть инструментов — работает с любым сайтом Moodle 3.x/4.x, где включены Web Services.

> Ни pip-пакетов, ни node, ни браузера. Только `python server.py`.

## Зачем это нужно

Агент умеет читать программу курса и подскажет, что сдавать завтра, но основная часть материалов курса скрыта за авторизацией. Скрапинг Moodle через headless-браузер медленный, хрупкий и часто упирается в WAF. У Moodle уже есть стабильный документированный REST API — не хватало лишь обёртки MCP.

Сервер использует только стандартную библиотеку Python (`urllib`, `json`, `ssl`) и общается по JSON-RPC 2.0 через stdio, поэтому подключается напрямую к Claude Desktop, Cursor, Marvis или любому MCP-совместимому клиенту.

## Инструменты

| Инструмент | Назначение | Параметры |
|---|---|---|
| `moodle_site_info` | Проверяет токен и возвращает название сайта, версию Moodle, текущего пользователя и список доступных аккаунту функций (диагностика). | — |
| `moodle_list_courses` | Список всех записанных курсов с ID, кратким и полным названием. | — |
| `moodle_recent_updates` | Материалы, добавленные или изменённые за последние N дней (задания, файлы, объявления), от новых к старым. | `days` (по умолчанию 7), `course_ids` |
| `moodle_pending_assignments` | Несданные задания, разбитые на **скоро дедлайн** / **просрочено** / **спокойно**, с дедлайном и остатком дней. | `ahead_days` (по умолчанию 14), `course_ids` |
| `moodle_course_files` | Структура разделов и список файлов одного курса, с прямыми ссылками на скачивание и датой изменения. **Возвращает только метаданные, файлы не скачиваются.** | `course_id` |
| `moodle_weekly_digest` | Сводка сразу: свежие изменения + ближайшие дедлайны + просрочки + статистика. Рекомендуется как отправная точка. | `days` (по умолчанию 7), `ahead_days` (по умолчанию 14) |

Все инструменты работают **только на чтение**. Интерфейсы сдачи, записи на курс, удаления и редактирования намеренно отсутствуют.

## Установка

### 1. Получение токена

Moodle требует персональный токен доступа. Выберите вариант по ситуации:

**A. Веб-интерфейс (рекомендуется, подходит и для SSO-аккаунтов)**

1. Войдите на свой сайт Moodle
2. Аватар → *Настройки* → *Аккаунт* → *Безопасность* → *Управление ключами доступа*
3. Нажмите «Создать», имя — `moodle-mcp`, служба — *Moodle mobile web service*
4. Скопируйте созданный ключ

**B. Скрипт через мобильный сервис (только если сайт хранит локальный пароль)**

```bash
python get_token.py
```

Скрипт получает токен через `/login/token.php` и службу `moodle_mobile_app` и сразу его проверяет. Пароль не отображается на экране и не пишется в лог. Для аккаунтов только с SSO вернётся `invalidlogin` — используйте вариант A.

**C. Переменные окружения**

```bash
MOODLE_URL=https://moodle.your-school.edu
MOODLE_TOKEN=your_token_here
```

### 2. Настройка

Создайте `config.json` в том же каталоге, что и `server.py`:

```json
{
  "url": "https://moodle.your-school.edu",
  "token": "your_token_here"
}
```

Переменные окружения имеют приоритет над файлом конфигурации.

### 3. Регистрация сервера

Claude Desktop / Cursor (`mcp.json`):

```json
{
  "mcpServers": {
    "moodle": {
      "command": "python",
      "args": ["/absolute/path/to/moodle-mcp/server.py"]
    }
  }
}
```

В `args` укажите абсолютный путь к `server.py`. Если установлено несколько версий Python, пропишите в `command` полный путь к интерпретатору.

## Известные ограничения

- **Turnitin (`turnitintooltwo`) и модуль `quiz` не поддерживаются.** Это отдельные модули без семантики `mod_assign`; их дедлайны нужно смотреть в веб-интерфейсе.
- Задания без установленного дедлайна отображаются как «не задан».
- Недельная сводка считает только **несданные** элементы; сданные, но не проверенные попадают в статистику и не выводятся в таблицах.
- Некоторые WAF отвечают `502` на последовательные запросы. Сервер уже сериализует вызовы с интервалом 150 мс; если ошибка сохраняется, повторите с большей паузой.
- На сайте должны быть включены Web Services, а у аккаунта должно быть право `webservice/rest:use`. Чаще всего выдаётся полный список функций, но бывает только мобильный набор.

## Безопасность

- Токен — это **учётные данные**. Храните его только в `config.json` или переменных окружения и не коммитьте в репозиторий; `.gitignore` уже исключает `config.json` и `get_token.log`.
- `get_token.py` не записывает пароль, только его длину, и читает ввод через `getpass`.
- Все инструменты работают только на чтение: даже при утечке токена через этот сервер нельзя изменить или удалить задания. При утечке отзовите ключ в разделе «Управление ключами доступа».
- Не публикуйте дампы трафика: `wstoken` передаётся в теле запроса.
